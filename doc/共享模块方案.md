# api-doc-go-share 共享模块方案（v1 草案）

> **范围**：`api-doc-go`（服务端，module `apidoc`）+ `api-doc-go-client`（桌面客户端，module `api-doc-go-client`）之间，把**语义必须一致的纯逻辑**收口到本仓库。
> **依据**：`api-doc-go/doc/客户端与同步架构设计.md`（D11/D12/F3、§8 可复用清单、§9.3 分层）+ 本次对两端代码的实测核对（2026-09-28）。
> **状态**：待拍板（文末 §9 列出 6 个决策点）。本文只定方案，不动代码。

---

## 1. 结论与依据

**结论**：变量渲染、代码生成、集合文件格式、OpenAPI/Postman 互转、Mock 匹配这几类「计算规则」可以且应当共享；框架层（gin/gorm/Wails）、平台与 IO、前端 UI 不共享。

**必须先解决的既成问题**：变量渲染规则**已经分叉**，直接抽库会把分叉固化。实测证据：

| # | 维度 | 服务端 `service/variable.go` | 客户端 `internal/varx/varx.go` |
|---|---|---|---|
| 1 | 占位符正则 | `\{\{\s*([A-Za-z_][A-Za-z0-9_]{0,63})\s*\}\}`（:24）——不允许 `$`，名字 ≤64 | `\{\{\s*(\$?[A-Za-z_][A-Za-z0-9_$]*)\s*\}\}`（:15）——允许 `$`，无长度上限 |
| 2 | 内置动态变量 | **无** | `$uuid/$timestamp/$isoTimestamp/$randomInt`（:18） |
| 3 | 优先级模型 | 请求1 > 项目当前环境2 > 项目通用(`env_id=0`)3 > 全局4（`varRank` :538）；同名取最高优先级 | 单环境 map + 内置覆盖；`envName==""` 时**合并全部环境**（客户端 `internal/app/app.go:194`） |
| 4 | 内置值生命周期 | — | `Builtins()` 在**每次 `$` 命中时重新生成**（:42）→ 同一文本里两个 `{{$uuid}}` 值不同 |

客户端 `varx` 的包注释写着「规则与设计文档一致」，而设计文档 D11 写着「语义必须一致的逻辑只允许一份实现」——**当前是两套实现**。这是本方案批次 2 要收敛的核心。

## 2. 共享边界：三条判据

任何代码要进 `api-doc-go-share`，必须同时满足：

1. **无框架依赖**：不 import gin / gorm / Wails runtime / 任何 `internal/{model,dto,repository,database,handler}`；
2. **无不可移植副作用**：纯计算，或只依赖标准库的可移植 IO（`encoding/*`、`net/url`、`crypto/*`）；**不**含真实网络、不绑定 `*gin.Context`、不负责进程/窗口；
3. **有两个使用方，或语义必须一致**：≥2 个消费方，或「两套实现必然漂移」（变量规则、文件格式、代码模板）。

### 三层归属

| 层 | 内容 | 归属 |
|---|---|---|
| **L1 纯逻辑（必须共享）** | `varx`（变量：语法/优先级/掩码/内置）、`codegen`（5 语言模板）、`collection`（集合文件**格式**）、`openapi`、`postman`、`mock`（路径匹配）、`request`（请求组装） | **本仓库** |
| **L2 契约（尽快）** | `contract/`（errcode + 契约常量）、`packages/api-client`（由 `doc/api_docs/**` 契约生成） | **本仓库**（批次 5） |
| **各自仓库** | 服务端：gin/gorm/`internal/{model,dto,repository,database,handler,service}`、`pkg/response`（吃 `*gin.Context`）<br>客户端：`internal/{app,platform,history,cookiejar}`、`config` 的 `Load/Save/Dir/Path`、`collection`/`runner` 的 IO 部分 | 不动 |
| **不共享** | 前端 UI 组件、i18n 文案、design tokens（设计文档 §9.2 已实测拍板「完全分离，小展示组件直接复制」；i18n 仅 ~128/407 键双端共用，按「两次法则」P3 后再议） | 各自仓库 |

> 注意：`server/internal/pkg/{errcode,page,fileutil,jwt,password,response}` 技术上可搬（依赖干净），但客户端**当前没有消费方**，本方案**不搬**（除 `errcode` 随批次 5 的契约一起进 L2）。移动它们只增加版本/CI 成本。

## 3. 目标仓库结构

```
api-doc-go-share/                     module: github.com/leihenshang/api-doc-go-share
├── go.mod                            go 1.25（取两端较低者：客户端 1.25.0、服务端 1.26）
├── .doc/共享模块方案.md               本文
├── varx/                             变量：占位符语法 / 优先级表 / 掩码 / 内置变量
├── codegen/                          curl · fetch · axios · go · python
├── collection/                       集合文件格式：结构 + YAML codec + round-trip + 命名规则
├── openapi/                          OpenAPI 3.0 导入 / 导出
├── postman/                          Postman Collection v2.1 导入 / 导出
├── mock/                             方法+路径匹配、路径归一化
├── request/                          请求组装（可返回 *http.Request，但不发请求）
└── contract/                         （批次 5）errcode + 契约常量
```

**关键原则：只搬「规则/格式」，不搬 IO 驱动。**

- 服务端是「收到文件内容（`dto.BrunoFile`）再解析」，客户端是「走 `os` 读目录」→ `collection/` 只提供结构体 + 编解码 + round-trip + 排序/命名规则；IO 各留各的。
- 客户端的 `internal/collection` 退化为「os IO + 调 share codec」，`internal/app/app.go`、`cmd/*` 的 import **基本不用改**（改造成本最低）。
- `request/` 只做组装（URL/params/body/multipart/auth/二进制判定），`net/http` 的 `Send/newClient/readResult` 留在客户端。

## 4. 工程组织与依赖

| 项 | 方案 |
|---|---|
| module path | 直接用 VCS 路径 `github.com/leihenshang/api-doc-go-share`（即使暂不发远端），避免将来改 import |
| 本地联调 | 在**父目录**放 `go.work`：`use ./api-doc-go/server ./api-doc-go-client ./api-doc-go-share`，**不入任何仓库**（加入各仓库 `.gitignore`）。两端 `go.mod` 零改动 |
| 正式依赖 | share 打语义化 tag（`v0.1.0`），两端 `go.mod` 里 `require` + `replace` 指向 tag；内网/私有 Git 需 `GOPRIVATE`。**不要提交相对路径 replace**（远程 CI 会因路径不存在失败） |
| Go 版本 | share 的 `go` 指令 **≤ 1.25**（客户端 1.25.0 是下限）；共享包内避免使用 1.26 才有的语言特性 |
| CI | ① 本仓库：`gofmt -l` → `go build ./...` → `go vet ./...` → `go test ./...`；② 校验 `go` 指令 ≤ 两端较低者；③ 消费方 CI 里额外 checkout share（或走 tag） |
| 版本策略 | 语义化版本；**破坏性变更必须两端同步改**，禁止在 share 里保留「兼容分支」把分叉藏回来 |

## 5. 变量语义归一（本方案的重点）

统一后的规则表（**建议值**，逐条见文末决策点）：

| 规则 | 建议 | 理由 / 影响面 |
|---|---|---|
| 占位符匹配 | `\{\{\s*(\$?[A-Za-z_][A-Za-z0-9_]{0,63})\s*\}\}` —— **渲染宽松（允许 `$`）、不再对渲染加长度上限**；64 位限制只保留为**写入校验** | 渲染加长度上限会让历史数据里超长名静默失效；写入时校验已经由服务端 `varNamePattern` 做了 |
| 未定义变量 | 原样保留 `{{name}}`，并把名字回传（去重保序） | 两端已一致（客户端 `missing`、服务端 `collectVarNames` 反推） |
| 空值变量 | 命中即替换为空串（不是「视为未定义」） | 服务端 `renderVars` 现行为，客户端一致 |
| 内置变量 | 统一 4 个：`$uuid` `$timestamp` `$isoTimestamp` `$randomInt`；**服务端新增支持**（纯增量，不影响既有接口） | 客户端已有；服务端缺失导致同一接口两端结果不同 |
| 内置值生命周期 | **一次 `Resolve` 内 memoize**：同一文本中两个 `{{$uuid}}` 取同一值 | 保证「URL 与 body 里同一个 `$uuid` 是一个值」；顺带修掉客户端每次命中重算（会生成不同值）——**见 D2** |
| `$` 未知内置名 | 原样保留，**不计入 missing** | 客户端现行为（`varx_test.go:44` 已固化） |
| 优先级 | 请求1 > 项目当前环境2 > 项目通用3 > 全局4；同名取最高优先级；`Enabled=false` 不参与；项目变量绑定「其它环境」时不参与 | 服务端 `varRank` 现行为，作为权威 |
| 客户端映射 | 客户端的「当前环境变量」→ `Scope=ScopeProjectEnv`；后续接项目级/全局时直接填 `Var` 即可，无需改 share | 让客户端先保持单层能力，同时不再另写一套渲染 |
| 掩码 | 常量 `••••••`；`HasValue = Value != ""`；`Secret && Value != ""` → 掩码 | 服务端 `maskVariable` 现行为；客户端暂未使用，供后续统一 |
| 环境合并 | `envName == ""` 时**不再合并全部环境**（客户端改成：无环境 = 只有内置变量） | 现客户端行为会让未选环境时意外命中其它环境的值 |

## 6. 迁移批次（每批独立可回滚）

> 红线：前三批都遵守「**只搬不改语义**」。批次 2 中与 §5 归一相关的变更是**有意变更**，必须单独标注、单独验收。

### 批次 0 — 骨架（0.5 天）
- 建 `go.mod`（go 1.25）、目录骨架、CI 三件套、父目录 `go.work`（gitignore）。
- **验收**：`go build ./...` 在联动下通过；两端仓库零改动。

### 批次 1 — codegen（零风险净收益，0.5 天）
- 服务端 `service/code.go` 的 `curlSnippet/fetchSnippet/axiosSnippet/goSnippet/pythonSnippet/jsQuote/codeHeaders` 搬进 `codegen/`，入参改中立 `codegen.Request`；服务端 `CodeSnippet` 保留（权限、审计、`model.Api` → 中立入参的映射）。
- 补 `codegen` 纯单测（对齐 `code_test.go` 的期望字符串）。
- **验收**：`go test ./internal/service -run TestCodeSnippetVariables` 原样通过。

### 批次 2 — varx 归一（1.5 天，含决策）
- 先冻结 §5 决策（D1/D2/D3）并回写 `客户端与同步架构设计.md` 的规则表。
- 实现 `varx`（Table + Builtins 注入）+ 纯单测（优先级矩阵、掩码、内置、缺失）。
- 服务端：`renderVars`/`varRank`/`maskVariable`/`collectVarNames` 改调 share（对外行为不变；`Variable`→`varx.Var` 映射留在 service）。
- 客户端：`internal/varx` 换成薄封装（导出签名不变）+ `app.envVars` 改走 share；按 §5 调整「空环境合并全部环境」。
- **验收**：服务端 `variable_test.go` 6 个用例原样通过；客户端 `varx_test.go` 原样通过（除 D2 有意变更，需显式改测试并注明）；新增「同文本两个 `{{$uuid}}` 同值」用例。

### 批次 3 — collection 格式（1.5 天）
- `collection/`：`Request/Meta/HTTP/Env/Manifest` 结构 + YAML codec + `Extra` 未知字段 round-trip + `ValidEnvName/SanitizeFileName/TrashName/SortNodes`。
- 服务端：`bruno.go` 的 `brunoInfo/KV/HTTP/Request/Folder` 换成 `collection.DecodeRequest`（`dto.BrunoFile` 只做输入适配）。
- 客户端：`internal/collection` 的 `requestFile/manifest/envFile/secretsFile` 换成 share 类型，IO 方法保留。
- **验收**：客户端 `request_file_test.go`（未知字段 round-trip、`auth: inherit`）、`folder_test.go`、服务端 `TestPostmanRoundTrip` 原样通过。

### 批次 4 — 互操作与 Mock（2 天）
- `openapi/`、`postman/`、`mock/`、`request/` 落地。
- 服务端 `export.go/postman.go/mock.go/extra.go` 改调。
- 客户端获得 **H6（代码生成）/H7（本地 Mock）/H9（Postman、OpenAPI 导入）** 的共享内核。
- **验收**：两端各自 `go test ./...` 全绿；用 `api-sample/bruno/project-A` 做跨仓库契约冒烟。

### 批次 5 — L2 契约（可选，1 天起）
- `contract/`（errcode + 契约常量）+ `packages/api-client`（由 `doc/api_docs/**` 生成），治理「改契约不改实现」。

## 8. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | 分叉的变量语义被固化 | 两端结果长期不一致 | 批次 2 前冻结决策并回写设计文档；share 内禁止「兼容开关」 |

| 3 | Go 版本指令不一致 | 客户端拉不动依赖 | share `go 1.25`；CI 校验 ≤ 两端较低者 |

| 6 | 迁移期两端行为短暂不一致 | 难定位 | 按批次推进，每批以「两端测试原样通过」为闸门 |

## 9. 待拍板决策点

| # | 决策 | 选项 | 推荐 |
|---|---|---|---|
| D1 | 渲染正则是否允许 `$` / 是否有长度上限 | (a) 渲染宽松（允许 `$`、不限长）+ 写入校验 64<br>(b) 两端都严格 64 且不支持 `$` | **(a)** |

| D5 | 发布方式 | (a) 语义化 tag + `GOPRIVATE`<br>(b) 长期本地 `replace` | **(a)**（先 `go.work` 稳定，再打 tag） |
| D6 | 是否搬 `server/internal/pkg/*` | (a) 暂不搬（无消费方）<br>(b) 顺手搬（`response` 需去 gin） | **(a)**（`errcode` 随批次 5 进 L2） |
